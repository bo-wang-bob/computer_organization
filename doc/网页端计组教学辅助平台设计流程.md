# 网页端计组教学辅助平台设计流程

## 一、项目定位

目标是设计一个网页端计组教学辅助平台，支持计算机组成原理课程中的：

- 章节知识问答
- 可视化推演
- 交互式仿真
- 汇编指令逐步解释
- 学习评价与反馈

整体思路是：**知识解释交给大模型，精确计算交给程序，动态展示交给前端，教学流程交给平台调度器组织。**

---

## 二、总体开发流程

建议将系统建设分为 8 个阶段，先完成最小可用版本，再逐步扩展复杂能力。

```text
第 1 步：明确平台的核心场景
第 2 步：设计知识体系与内容库
第 3 步：确定系统总体架构
第 4 步：开发最小可用版本 MVP
第 5 步：加入可视化推演能力
第 6 步：开发交互式仿真模块
第 7 步：设计平台工作流
第 8 步：开展教学评价与迭代
```

---

## 三、第 1 步：明确平台的核心场景

首先需要明确系统到底解决哪些教学问题，而不是一开始就设计成万能系统。

当前需求可以拆解为 4 类核心能力：

| 能力 | 用户想完成什么 |
|---|---|
| 章节知识问答 | 学生询问课程概念、原理、公式、例题 |
| 可视化推演 | 将抽象过程转化为图形化、步骤化展示 |
| 交互式仿真 | 学生修改输入参数，观察系统状态变化 |
| 汇编指令逐步解释 | 输入汇编代码，逐条解释寄存器、内存、控制过程 |

### 建议第一版重点支持的章节

建议第一版优先聚焦高频、适合可视化和仿真的内容：

1. 数据表示：原码、反码、补码、浮点数  
2. 运算器：加减法、溢出、乘除法  
3. 指令系统：指令格式、寻址方式、汇编解释  
4. CPU：数据通路、控制信号、流水线  
5. 存储系统：Cache 映射、命中率、地址划分  

---

## 四、第 2 步：设计知识体系与内容库

平台中问答能力的质量不仅取决于大模型，也取决于知识库的组织方式。

建议将课程内容组织为三层。

### 1. 知识点层

以“补码”为例：

```text
补码
├── 为什么需要补码
├── 补码表示规则
├── 补码加法
├── 补码减法
├── 溢出判断
└── 典型例题
```

### 2. 教学解释层

每个知识点不只保存定义，还应包含：

```text
概念解释
直观类比
公式推导
典型例题
常见误区
可视化方案
课后小测
```

### 3. 结构化数据层

为了支持可视化推演和交互式仿真，需要将关键过程结构化。

例如补码加法：

```json
{
  "topic": "补码加法",
  "input": ["x = +5", "y = -3"],
  "binary_steps": [
    "x = 00000101",
    "y = 11111101",
    "sum = 00000010"
  ],
  "result": "+2",
  "overflow": false
}
```

普通 RAG 知识库主要支持问答，而可视化推演和交互式仿真需要额外的结构化过程数据。

## 五、第 3 步：确定系统总体架构

网页端计组教学辅助平台可以采用如下架构：

```text
前端页面
  ├── 聊天问答区
  ├── 可视化推演区
  ├── 仿真控制区
  └── 汇编代码输入区

后端服务
  ├── 平台调度模块
  ├── 课程知识库检索模块
  ├── 推理与解释生成模块
  ├── 可视化数据生成模块
  ├── 仿真执行模块
  └── 汇编解释模块

数据层
  ├── 课程教材 / 讲义
  ├── 知识点结构库
  ├── 例题库
  ├── 指令语义库
  └── 仿真规则库
```

### 核心设计原则

不要让大模型承担所有工作。

建议采用：

```text
大模型：负责理解问题、组织语言、生成教学解释
规则程序：负责补码计算、Cache 地址划分、流水线推进等确定性推演
前端组件：负责动画、表格、流程图、状态变化展示
平台调度器：负责判断用户意图并调用不同模块
```

## 六、第 4 步：开发最小可用版本 MVP

第一版不建议同时实现所有能力，而应先做一个稳定可用的最小版本。

### MVP 功能一：章节知识问答

支持学生提问，例如：

```text
为什么补码可以把减法变成加法？
Cache 直接映射和组相联映射有什么区别？
指令周期和机器周期有什么关系？
```

实现流程：

```text
课程资料
  ↓
文本切分
  ↓
向量化
  ↓
知识检索
  ↓
大模型生成回答
```

### MVP 功能二：基础汇编指令逐步解释

先支持少量基础指令，例如：

```asm
MOV R1, #5
MOV R2, #3
ADD R3, R1, R2
```

输出示例：

```text
第 1 步：MOV R1, #5
含义：将立即数 5 写入寄存器 R1
执行后：R1 = 5

第 2 步：MOV R2, #3
含义：将立即数 3 写入寄存器 R2
执行后：R2 = 3

第 3 步：ADD R3, R1, R2
含义：R3 = R1 + R2
执行后：R3 = 8
```

### MVP 功能三：补码推演

输入：

```text
x = +5
y = -3
位数 = 8 位
```

输出：

```text
+5 的补码：00000101
-3 的补码：11111101
相加结果：00000010
最终结果：+2
是否溢出：否
```

## 七、第 5 步：加入可视化推演能力

可视化推演是计组教学辅助平台区别于普通聊天工具的关键优势。

### 优先支持的可视化内容

| 知识点 | 可视化形式 |
|---|---|
| 补码加法 | 二进制位逐位相加、进位变化 |
| 溢出判断 | 符号位、进位、结果范围高亮 |
| 浮点数表示 | 符号位、阶码、尾数拆分 |
| Cache 映射 | 主存块映射到 Cache 行 |
| 指令流水线 | IF、ID、EX、MEM、WB 时间表 |
| 数据通路 | 指令执行时各部件连线高亮 |

### 可视化数据设计示例

以流水线为例，后端可以返回：

```json
{
  "type": "pipeline",
  "instructions": ["I1", "I2", "I3"],
  "stages": ["IF", "ID", "EX", "MEM", "WB"],
  "timeline": [
    ["IF", "ID", "EX", "MEM", "WB"],
    ["", "IF", "ID", "EX", "MEM"],
    ["", "", "IF", "ID", "EX"]
  ]
}
```

前端根据该 JSON 数据渲染为表格、动画或流程图。

## 八、第 6 步：开发交互式仿真模块

仿真模块建议独立开发，尽量不要完全依赖大模型。

可以按章节拆成多个小仿真器。

### 1. 数据表示仿真器

输入：

```text
十进制数：-13
位数：8 位
表示方式：补码
```

输出：

```text
原码：10001101
反码：11110010
补码：11110011
```

### 2. 缓存仿真器

输入：

```text
主存地址：0x3A7
Cache 行数：16
块大小：4B
映射方式：直接映射
```

输出：

```text
块内地址：2 bit
Cache 行号：4 bit
Tag：剩余高位
是否命中：根据当前 Cache 状态判断
```

### 3. 流水线仿真器

输入：

```asm
ADD R1, R2, R3
SUB R4, R1, R5
```

输出：

```text
存在 RAW 数据冒险
SUB 指令需要等待 ADD 写回 R1
可通过暂停或转发解决
```

### 4. 汇编执行仿真器

需要维护以下状态：

```text
寄存器状态
内存状态
程序计数器 PC
当前指令
执行阶段
标志位状态
```

建议从简化 ISA 开始，不要一开始就支持完整 x86 或 ARM 指令集。

## 九、第 7 步：设计平台工作流

平台不应该只是一个“大模型回答器”，而应包含任务识别、规则工具调用和可视化组织能力。

### 总体工作流

```text
用户输入
  ↓
意图识别
  ↓
判断任务类型
  ├── 知识问答 → 检索课程知识库 → 生成解释
  ├── 例题讲解 → 调用推演模块 → 生成步骤
  ├── 可视化请求 → 生成结构化可视化数据
  ├── 仿真请求 → 调用仿真器 → 返回状态变化
  ├── 汇编解释 → 调用指令解析器 → 逐步解释
  └── 学习评价 → 分析作答记录 → 诊断薄弱知识点并推荐练习
```

### 示例一：汇编解释任务

用户输入：

```text
帮我解释一下这段汇编每一步做了什么
```

执行流程：

```text
识别为汇编解释任务
  ↓
调用汇编解析器
  ↓
模拟寄存器变化
  ↓
生成逐步解释
  ↓
前端展示代码高亮 + 状态表
```

### 示例二：知识问答任务

用户输入：

```text
为什么补码减法可以转成加法？
```

执行流程：

```text
识别为知识问答任务
  ↓
检索补码相关知识
  ↓
生成概念解释
  ↓
给出二进制例子
  ↓
可选生成可视化推演
```

## 十、第 8 步：开展教学评价与迭代

系统上线后需要持续评估，而不是只看能不能回答问题。

### 评价指标

| 指标 | 评估问题 |
|---|---|
| 正确性 | 计算结果、概念解释是否正确 |
| 可解释性 | 学生是否能看懂每一步 |
| 交互性 | 学生能否修改输入并观察变化 |
| 鲁棒性 | 输入错误代码时能否提示原因 |
| 教学适配性 | 是否符合课程章节和教学目标 |
| 可视化质量 | 图示是否真正帮助理解 |
| 可扩展性 | 是否方便增加新章节、新仿真器 |

### 测试集设计

建议准备一套教学测试集：

```text
100 个章节知识问答
50 个补码 / 浮点数推演题
50 个 Cache 地址划分题
50 个流水线冒险分析题
50 段汇编指令解释题
若干错误输入与边界案例
```

每次系统更新后都运行测试集，检查是否出现能力退化。

## 十一、推荐开发路线

建议按如下顺序推进：

```text
第 1 阶段：章节知识问答
第 2 阶段：补码 / 浮点数 / Cache 的规则推演
第 3 阶段：汇编指令逐步解释
第 4 阶段：前端可视化展示
第 5 阶段：交互式仿真
第 6 阶段：流水线、数据通路等复杂动态仿真
第 7 阶段：教师端管理与题库评测
```

最合理的 MVP 是：

```text
知识问答 + 补码推演 + 简单汇编逐步解释
```

## 十三、最终系统模块划分

最终可以将平台划分为 6 类教学辅助能力，必要时由内部 AI 调度或专门服务实现：

```text
1. 课程问答能力
2. 例题讲解能力
3. 可视化推演能力
4. 汇编解释能力
5. 交互仿真能力
6. 学习评价能力
```

它们共享同一个课程知识库，但分别调用不同工具或模块。

### 1. 课程问答能力

课程问答能力是平台的基础入口，负责回答学生对课程概念、原理、公式、术语关系和常见误区的提问。

主要功能：

- 识别学生问题对应的章节和知识点，例如补码、Cache、流水线、指令周期等。
- 检索课程知识库、教材笔记、术语表和公式说明，生成面向学生的分层解释。
- 对容易混淆的概念进行对比说明，例如指令周期、机器周期、时钟周期的区别。
- 在回答末尾给出后续学习建议，例如推荐例题、可视化推演或交互仿真。
- 对学生表述不完整的问题进行追问或补充假设，避免直接给出不可靠答案。

输入包括：学生自然语言问题、当前章节、学习阶段、历史对话上下文。

输出包括：概念解释、关键结论、必要公式、简短例子、常见误区、下一步学习建议。

依赖模块包括：课程知识库检索、术语库、公式库、大模型解释生成模块。

职责边界：课程问答能力不负责复杂数值计算和状态仿真。涉及补码计算、Cache 地址划分、流水线时序等确定性推演时，应调用例题讲解能力、可视化推演能力或交互仿真能力。

### 2. 例题讲解能力

例题讲解能力负责把一道题拆成可理解、可检查、可复盘的解题过程，重点解决“这道题为什么这么做”的问题。

主要功能：

- 解析题干条件、已知量、目标量和隐含约束。
- 判断题型，例如补码运算、浮点数表示、Cache 地址划分、流水线冒险、指令格式分析等。
- 调用规则推演模块完成确定性计算，保证中间结果和最终答案正确。
- 生成逐步讲解，包括解题思路、每一步依据、关键公式、结果校验。
- 根据学生水平切换讲解粒度，例如提示模式、完整解析模式、考试速解模式。
- 生成同类变式题或下一道练习题，用于巩固当前知识点。

输入包括：题目文本、题型标签、学生答案、期望讲解深度、是否需要提示。

输出包括：题型判断、解题思路、步骤化过程、最终答案、易错点、变式练习建议。

依赖模块包括：例题库、公式库、补码 / 浮点数 / Cache / 流水线等规则推演工具。

职责边界：例题讲解能力侧重“解题过程说明”。如果学生需要动画、表格高亮或状态变化图，应把结构化步骤交给可视化推演能力；如果学生需要反复修改参数观察结果，应交给交互仿真能力。

### 3. 可视化推演能力

可视化推演能力负责把抽象计算过程转换成前端可以展示的结构化数据，让学生看见每一步状态如何变化。

主要功能：

- 为补码加法、溢出判断、浮点数拆分、Cache 映射、流水线推进、数据通路等内容生成逐步状态。
- 将规则工具输出转换为统一的可视化数据格式，例如时间线、表格、节点连线、高亮区域和状态差异。
- 给每个可视化步骤生成简短说明，解释当前高亮内容代表什么。
- 标记关键变化点，例如进位变化、符号位异常、Cache 命中 / 缺失、流水线暂停、数据冒险。
- 根据前端展示能力选择合适形式，例如表格、流程图、时序图、寄存器状态面板。

输入包括：知识点类型、题目参数、规则推演结果、期望展示形式、当前步骤编号。

输出包括：可视化 JSON 数据、步骤说明、关键状态变化、前端高亮指令。

依赖模块包括：规则推演工具、可视化数据生成模块、前端图表组件。

职责边界：可视化推演能力不直接决定计算结果，计算结果必须来自规则程序或仿真器。它的核心职责是“把正确过程组织成可展示过程”。

### 4. 汇编解释能力

汇编解释能力负责解释汇编代码的语义和执行过程，帮助学生理解指令、寄存器、内存、PC 和控制流程之间的关系。

主要功能：

- 解析简化 ISA 或指定汇编子集中的指令，例如 MOV、ADD、SUB、LW、SW、ADDI 等。
- 逐条说明指令含义、操作数来源、写回目标和执行后状态变化。
- 模拟寄存器、内存、PC、标志位等状态，生成每一步执行快照。
- 识别常见错误，例如未知指令、寄存器名错误、立即数格式错误、访存地址不合法。
- 在涉及流水线时，提示数据冒险、控制冒险、结构冒险及可能的暂停或转发方案。

输入包括：汇编代码、ISA 类型、初始寄存器状态、初始内存状态、是否按流水线解释。

输出包括：指令解析表、逐条解释、状态变化表、最终寄存器 / 内存状态、错误或风险提示。

依赖模块包括：汇编解析器、指令语义库、简化 ISA 解释器、寄存器 / 内存状态模拟器。

职责边界：第一阶段不追求完整支持 x86 或 ARM 指令集，应优先支持教学用简化 ISA 或 RISC-V 子集。遇到未支持指令时，需要明确提示支持范围，而不是编造执行结果。

### 5. 交互仿真能力

交互仿真能力负责管理可重复、可操作、可观察的仿真实验，让学生通过修改参数和逐步执行来理解系统行为。

主要功能：

- 创建和维护仿真会话，例如数据表示仿真、Cache 仿真、流水线仿真、汇编执行仿真。
- 支持重置、单步执行、连续执行、暂停、修改参数、回到上一步等交互操作。
- 记录每一步状态变化，形成状态差异和事件日志。
- 对学生修改的参数进行合法性检查，例如位数、地址范围、Cache 行数、块大小、指令格式。
- 在仿真过程中解释当前状态，例如为什么 Cache 未命中、为什么流水线暂停、为什么寄存器被改写。
- 支持对比实验，例如直接映射和组相联映射的命中情况对比。

输入包括：仿真类型、初始参数、当前会话 ID、用户操作、运行步数。

输出包括：当前状态、下一步状态、状态差异、事件日志、可视化数据、提示信息。

依赖模块包括：各类规则仿真器、会话状态存储、可视化推演能力、前端交互控件。

职责边界：交互仿真能力不应让大模型直接生成状态变化。大模型只负责解释和引导，状态更新必须由规则仿真器完成。

### 6. 学习评价能力

学习评价能力负责根据学生的作答、练习记录和交互过程判断学习掌握情况，并给出个性化反馈。

主要功能：

- 批改客观题、推演题和部分结构化主观题，判断答案是否正确。
- 分析错误类型，例如概念混淆、公式套用错误、二进制位数错误、Cache 字段划分错误、流水线冒险判断错误。
- 建立知识点掌握画像，记录学生在章节、题型和能力维度上的薄弱点。
- 根据错误原因推荐复习内容、例题讲解、可视化推演或交互仿真任务。
- 为教师端生成班级层面的统计摘要，例如高频错题、薄弱章节、题目区分度。
- 跟踪学习进步，比较多次练习后的正确率、用时、提示次数和错误类型变化。

输入包括：学生答案、标准答案或评分规则、练习记录、知识点标签、学习目标。

输出包括：评分结果、错误诊断、掌握度估计、个性化反馈、后续练习推荐、教师端统计摘要。

依赖模块包括：题库、评分规则、学习记录数据库、知识点图谱、统计分析模块。

职责边界：学习评价能力不应替代教师对开放性大作业的最终判断。对无法自动可靠评分的开放题，应给出参考性诊断并标记为需要人工复核。

### 教学辅助能力协作关系

建议由平台调度器统一识别用户意图，再调用上述教学辅助能力：

```text
课程问答能力：负责解释“是什么、为什么”
例题讲解能力：负责讲清“一道题怎么做”
可视化推演能力：负责展示“过程怎么变化”
汇编解释能力：负责说明“代码每一步做什么”
交互仿真能力：负责支持“改参数后会怎样”
学习评价能力：负责判断“学得怎么样、下一步练什么”
```

其中课程知识库、例题库、规则推演工具和学习记录应作为共享资源，避免每个能力模块维护一套互相不一致的数据。

## 十四、核心总结

整个系统建设可以概括为：

```text
从课程知识库开始，
以知识问答作为入口，
用规则模块保证推演正确，
用前端可视化增强理解，
用仿真器支持交互探索，
最终形成面向计算机组成原理的教学辅助平台。
```

最重要的设计原则是：

```text
大模型负责解释，
规则程序负责计算，
前端负责展示，
平台调度器负责调度。
```
