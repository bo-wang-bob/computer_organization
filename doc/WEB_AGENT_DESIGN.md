# 计算机组成原理网页端智能体设计文档

## 1. 项目定位

本项目面向《计算机组成原理》课程建设一个网页端教学智能体。它不是单纯的问答机器人，而是一个能够围绕课程知识进行讲解、推演、仿真、诊断和练习推荐的交互式学习助教。

核心目标：

- 帮助学生把抽象的硬件结构、指令执行和存储层次过程可视化。
- 帮助学生通过交互式仿真理解计算机组成原理中的关键计算过程。
- 帮助教师沉淀课程知识库、实验案例和高频错因。
- 在问答之外提供“过程型学习”：让学生能看到每一步为什么这样发生。

## 2. 目标用户

### 2.1 学生

典型需求：

- 课前预习章节知识。
- 课后复习重点概念。
- 做题时获得分步骤提示，而不是直接看答案。
- 理解流水线、Cache、补码、浮点数、寻址方式等抽象过程。
- 在实验中检查汇编指令、寄存器状态、数据通路变化。

### 2.2 教师

典型需求：

- 配置课程章节、教材范围和知识点。
- 生成课堂提问、小测题、实验引导材料。
- 查看学生常见错误和薄弱知识点。
- 管理智能体回答依据，避免知识漂移。

## 3. MVP 能力范围

第一阶段建议围绕五个核心能力实现。

### 3.1 章节知识问答

学生可以围绕课程章节进行自然语言提问，智能体需要结合课程知识库回答。

能力要求：

- 支持按章节检索：数据表示、运算器、指令系统、CPU、流水线、存储系统、I/O。
- 回答时标明关联知识点。
- 根据学生基础切换讲解深度：入门解释、考试题视角、实验实现视角。
- 对计算类问题展示公式、步骤和结果。
- 对容易混淆的概念主动比较，例如补码溢出与无符号进位、Cache 块号与组号、硬布线控制与微程序控制。

示例交互：

```text
学生：为什么补码加法可以统一处理正数和负数？
智能体：先从模运算角度解释，再给出 4 位补码例子，最后提醒溢出判断规则。
```

### 3.2 可视化推演

对计算机组成中的动态过程进行图形化展示，支持逐步播放、暂停和回退。

优先场景：

- 指令周期：取指、译码、执行、访存、写回。
- 单周期 CPU 数据通路：PC、寄存器堆、ALU、数据存储器、控制信号。
- 五级流水线：IF、ID、EX、MEM、WB。
- 流水线冒险：结构冒险、数据冒险、控制冒险。
- Cache 访问过程：地址拆分、命中判断、替换策略。

交互要求：

- 每一步高亮当前活跃部件和数据流。
- 旁边同步显示“当前发生了什么”和“为什么发生”。
- 支持切换“学生模式”和“教师演示模式”。
- 对流水线题支持周期表展示。

### 3.3 交互式仿真

学生输入参数或代码，系统实时计算并展示中间状态。

优先仿真器：

- 进制与补码转换仿真器。
- 定点加减法与溢出判断仿真器。
- 浮点数表示仿真器。
- Cache 地址划分与命中率仿真器。
- 流水线执行周期仿真器。

每个仿真器都应包含：

- 输入区：题目参数、指令序列或地址序列。
- 状态区：寄存器、内存、Cache、流水线表等。
- 推导区：逐步展示中间计算。
- 反馈区：指出学生输入是否合理、错在哪里。

### 3.4 汇编指令逐步解释

学生输入一段汇编代码后，智能体逐条解释指令语义、寄存器变化和内存访问。

建议优先支持 RISC-V RV32I，后续可扩展 MIPS 或 LoongArch。

能力要求：

- 识别指令类型：R 型、I 型、S 型、B 型、U 型、J 型。
- 解释字段含义：opcode、rd、rs1、rs2、funct3、funct7、imm。
- 展示每条指令对寄存器和内存的影响。
- 支持逐步执行、单步回退、重置。
- 对分支跳转展示 PC 变化。
- 对 load/store 展示有效地址计算。

示例输入：

```asm
addi x1, x0, 5
addi x2, x0, 7
add  x3, x1, x2
sw   x3, 0(x0)
```

示例输出重点：

- 第 1 条：x1 = x0 + 5 = 5。
- 第 2 条：x2 = x0 + 7 = 7。
- 第 3 条：x3 = x1 + x2 = 12。
- 第 4 条：Memory[0] = x3 = 12。

### 3.5 学习诊断与练习推荐

智能体根据学生提问、仿真输入和答题结果判断薄弱点，并推荐下一步练习。

诊断维度：

- 概念缺失：不知道术语或基本定义。
- 规则误用：知道公式但用错场景。
- 过程断点：推导中间步骤缺失。
- 表达错误：会做但答题表述不规范。
- 实验错误：代码、波形或寄存器状态与预期不符。

反馈原则：

- 优先指出第一个关键错误。
- 给出提示，再给完整答案。
- 生成同类型但参数不同的巩固题。
- 记录学生知识点掌握情况。

## 4. 信息架构

网页端建议采用左侧导航加主工作区布局。

### 4.1 页面结构

- 首页工作台：展示最近学习、推荐练习、快捷入口。
- 章节问答页：章节目录、问答窗口、引用知识点。
- 可视化推演页：场景选择、图形推演区、步骤说明区。
- 交互式仿真页：仿真器列表、参数输入、运行结果。
- 汇编解释页：代码编辑器、寄存器面板、内存面板、执行日志。
- 练习诊断页：题目、作答区、批改结果、错因归类。
- 教师配置页：课程知识库、章节结构、题库、智能体策略。

### 4.2 推荐首屏

学生登录后的首屏不做营销页，而是直接进入学习工作台。

首屏内容：

- 当前章节学习进度。
- 三个快捷操作：问一个问题、运行一个仿真、解释一段汇编。
- 今日推荐练习。
- 最近一次错误诊断。

## 5. 核心用户流程

### 5.1 章节问答流程

1. 学生选择章节或直接提问。
2. 系统检索课程知识库。
3. 智能体生成回答。
4. 系统附带知识点标签、难度、相关练习。
5. 学生可以点击“再举例”“出一道类似题”“换成实验视角解释”。

### 5.2 可视化推演流程

1. 学生选择推演场景，例如五级流水线。
2. 输入指令序列或选择示例。
3. 系统生成周期表和流水线状态。
4. 学生点击单步执行。
5. 页面同步高亮阶段、数据流、冒险点和解决方式。

### 5.3 交互式仿真流程

1. 学生选择仿真器，例如 Cache 地址划分。
2. 输入 Cache 参数和访存地址。
3. 系统校验参数。
4. 仿真器计算地址字段、命中情况和替换过程。
5. 智能体解释每一步计算。

### 5.4 汇编解释流程

1. 学生输入汇编代码。
2. 系统解析指令并初始化寄存器和内存。
3. 学生单步执行。
4. 页面展示当前指令、控制信号、寄存器变化和内存变化。
5. 智能体解释每条指令对 CPU 状态的影响。

### 5.5 诊断推荐流程

1. 学生完成练习或提交推导步骤。
2. 系统进行结构化批改。
3. 智能体判断错因。
4. 系统更新学习画像。
5. 推荐下一组练习或回到对应知识点。

## 6. 前端界面设计

### 6.1 总体风格

建议采用偏教学工具风格：

- 信息密度适中，方便课堂投屏和学生自学。
- 色彩用于表达状态：执行中、命中、缺失、错误、提示。
- 避免装饰性过强的视觉元素，重点突出图、表、状态变化。
- 可视化模块优先保证清晰和可读。

### 6.2 关键组件

- 章节树：用于浏览课程结构。
- 智能问答框：支持普通问答、提示式问答和追问。
- 代码编辑器：用于汇编输入，建议支持语法高亮。
- 寄存器表：展示 x0-x31 或指定 ISA 的寄存器。
- 内存表：展示地址和值。
- 流水线周期表：行是指令，列是周期。
- 数据通路画布：展示 CPU 部件和连线状态。
- Cache 视图：展示组、路、标记位、有效位、脏位、数据块。
- 步骤控制条：开始、暂停、上一步、下一步、重置。
- 错因标签：概念错误、计算错误、规则误用、步骤遗漏。

## 7. 技术架构

建议采用前后端分离架构。

### 7.1 前端

可选技术栈：

- React 或 Vue。
- TypeScript。
- Vite。
- Canvas/SVG 用于数据通路和流水线可视化。
- Monaco Editor 或 CodeMirror 用于汇编编辑器。
- Zustand/Pinia 用于局部状态管理。

前端职责：

- 展示页面和交互状态。
- 执行轻量级本地仿真。
- 调用后端智能体 API。
- 渲染可视化步骤。

### 7.2 后端

可选技术栈：

- Python FastAPI 或 Node.js NestJS。
- 向量数据库用于课程知识检索。
- 关系数据库用于用户、学习记录、题库。
- 大模型 API 用于问答、解释和诊断。

后端职责：

- 管理课程知识库。
- 管理题库和练习记录。
- 执行复杂解析和批改。
- 封装大模型调用。
- 对智能体输出进行格式约束和安全控制。

### 7.3 智能体服务

智能体不应直接自由生成所有内容，而应采用“工具 + 检索 + 结构化输出”的方式。

推荐组件：

- 课程知识检索工具。
- 汇编解析工具。
- Cache 仿真工具。
- 流水线仿真工具。
- 练习批改工具。
- 错因诊断工具。

## 12. 教学策略

### 12.1 分层讲解

同一问题支持三种回答深度：

- 入门：面向刚接触概念的学生，类比和图示优先。
- 标准：面向课程考试，强调定义、公式和步骤。
- 深入：面向实验和实现，强调硬件结构、控制信号和状态变化。

### 12.2 提示优先

练习场景中默认不直接给最终答案。

推荐提示阶梯：

1. 指出应关注的知识点。
2. 提醒使用哪条规则。
3. 给出下一步计算。
4. 给出完整解答。

### 12.3 可解释批改

批改时不只返回对错，还要返回：

- 错误发生在哪一步。
- 错误属于哪类。
- 正确规则是什么。
- 下一题应该练什么。

## 13. 安全与可信设计

- API Key 不应放在前端代码或可提交配置中，应由后端环境变量或密钥管理服务读取。
- 大模型回答必须优先依据课程知识库。
- 对没有依据的问题应明确说明“不在当前课程范围内”或“知识库未覆盖”。
- 对计算题应使用确定性工具计算结果，再由智能体解释。
- 对汇编和仿真结果应由解析器/仿真器生成，不应完全依赖大模型自由推断。
- 教师应能审核和修订知识库内容。

## 14. 推荐实现里程碑

### 阶段一：基础学习助教

- 完成课程章节结构。
- 完成章节知识问答。
- 完成题目解释和提示式回答。
- 完成基础学习记录。

### 阶段二：核心仿真器

- 完成补码与溢出仿真器。
- 完成 Cache 地址划分仿真器。
- 完成五级流水线周期表生成。
- 完成基础可视化播放控件。

### 阶段三：汇编解释器

- 支持 RISC-V RV32I 常用整数指令。
- 支持寄存器和内存状态展示。
- 支持单步执行和执行日志。
- 支持与数据通路视图联动。

### 阶段四：诊断与教师端

- 完成练习批改。
- 完成错因分类。
- 完成学习画像。
- 完成教师端知识库与题库配置。

## 15. 首版验收标准

首版可用系统至少应满足：

- 学生能按章节提问，并获得结构化、可追问的回答。
- 学生能输入一组 Cache 参数和地址，并看到地址拆分、命中判断和解释。
- 学生能输入一组简单 RISC-V 指令，并逐步查看寄存器变化。
- 学生能查看至少一种流水线周期表和冒险提示。
- 学生做错一道典型题时，系统能指出第一处关键错误并推荐练习。
- 教师能配置至少一份课程知识内容和一组题库。
